    Router setup

    Connect a MikroTik router to HotspotPlus Lite: RADIUS, Disconnect, the hotspot profile, the login page and the firewall.

    Overview

    This page assumes that the hotspot feature already works on your MikroTik router (a hotspot server, a hotspot profile and an address pool). You then change 3 things. The router asks HotspotPlus Lite about each login over RADIUS (the protocol the router uses to ask the server about each login), and it sends accounting packets (usage updates during a session). The router accepts Disconnect requests. The router uses a login page from HotspotPlus Lite.

    Step 1: the shared secret

    In the admin panel, open the Settings page. Note the RADIUS shared secret. The server made a random one at the first start, or it used the value of HSP_RADIUS_SHARED_SECRET. You can change it. Use letters and digits only (no spaces or symbols). Make it long and random: 20 or more characters. Also note the Disconnect (CoA) port (the router port that gets Disconnect requests). It is 3799 by default.

    Step 2: the setup script

    Open the Router page (/admin/router). It shows a RouterOS setup script with your shared secret and ports filled in. It looks like this:

    # 1. RADIUS server. Replace <SERVER-IP>, and use the secret from the Settings page.
/radius add service=hotspot address=<SERVER-IP> secret="YOUR-SHARED-SECRET" authentication-port=1812 accounting-port=1813 timeout=5s

# 2. Accept Disconnect requests on the port from the Settings page (3799 by default).
/radius incoming set accept=yes port=3799

# 3. Hotspot profile: use RADIUS, PAP login, accounting every 60 seconds.
/ip hotspot profile set [find name=hsprof1] use-radius=yes login-by=http-pap radius-accounting=yes radius-interim-update=60s
    • Replace <SERVER-IP> with the address of the computer that runs HotspotPlus Lite, as the router sees it. In the script on the Router page, the /radius add line is commented out until you do this.
    • Replace hsprof1 with the name of your hotspot profile. To list the names, run /ip hotspot profile print.
    • You need login-by=http-pap, because the server accepts only PAP (the login method where the router sends the password to the server). With CHAP, every login fails.
    • The accounting interval in the script is the value from the Settings page (60 seconds by default).

    Choose Copy script, then paste the script into a RouterOS terminal (WinBox or SSH). Or save it as setup.rsc and run /import setup.rsc. The script contains the shared secret, so do not share it.

    Step 3: the login page

    On the same Router page, under Sign-in pages, choose a design and click Download (Open preview shows it first). You get a zip file with a folder named hotspot. Unzip it. Then upload the hotspot folder to the router (with Files in WinBox, or with FTP) and replace the old one. On routers that keep files on flash storage, the folder is flash/hotspot.

    See Hotspot login pages for the designs and how to edit them.

    Firewall

    These ports must be open. The server never talks to members. It talks only to the router and to you:

    WhereRule
    On the server, from the routerUDP 1812 (login) and UDP 1813 (accounting), inbound.
    On the server, from your computerTCP 8080 (admin panel), inbound. Do not allow it from the hotspot network.
    On the router, from the serverUDP 3799 (Disconnect requests), inbound. The router must accept this traffic. The command /radius incoming set accept=yes port=3799 turns on the listener.
    Server on the hotspot network

    If the server is on the hotspot network, the router may treat it as a guest and ignore its replies. Logins then fail with RADIUS server is not responding. See Hotspot on Wi-Fi only.

    Disconnect requests have a similar problem. The server sends them to the address the router used for accounting. The router's default firewall drops traffic that arrives from its uplink.

    For example, on Linux with ufw (replace the addresses):

    sudo ufw allow from ROUTER-IP to any port 1812 proto udp
sudo ufw allow from ROUTER-IP to any port 1813 proto udp
sudo ufw allow from ADMIN-PC-IP to any port 8080 proto tcp

    On Windows, see the netsh commands in Run as a service. To keep the admin panel off the hotspot network, you can also bind it to one address. For example, set HSP_ADMIN_ADDR=192.168.1.10:8080 for the first start, or change the address on the Settings page later.

    Hotspot on Wi-Fi only

    If Wi-Fi and the LAN ports are in one bridge and the hotspot runs on that bridge, every device on it is a hotspot guest, including the server. The router then ignores the server's replies, and logins fail with RADIUS server is not responding.

    Fix (recommended): use two bridges. Keep the existing bridge for the LAN ports (with the server) and run no hotspot on it. Make a new bridge with only the Wi-Fi interface, give it its own subnet and a DHCP server, and run the hotspot only on the new bridge.

    1. Back up first: /export file=before-split.
    2. Do the change over a LAN port, not over Wi-Fi.
    3. /ip hotspot remove deletes the current hotspot server, so note its settings first.
    4. Run the commands. Replace wlan1, the addresses, and hsprof1 with your own values.
    /interface bridge add name=bridge-wifi
/interface bridge port remove [find interface=wlan1]
/interface bridge port add bridge=bridge-wifi interface=wlan1
/ip address add address=10.5.50.1/24 interface=bridge-wifi
/ip pool add name=pool-wifi ranges=10.5.50.10-10.5.50.250
/ip dhcp-server add name=dhcp-wifi interface=bridge-wifi address-pool=pool-wifi disabled=no
/ip dhcp-server network add address=10.5.50.0/24 gateway=10.5.50.1 dns-server=10.5.50.1
/ip hotspot remove [find]
/ip hotspot add name=hotspot-wifi interface=bridge-wifi address-pool=pool-wifi profile=hsprof1

    After that, run the setup script again. Check that the NAT masquerade rule covers the new subnet. If a /radius src-address is set, it must be the router's LAN address.

    Quick option: keep one bridge and bypass only the server and the admin PC. Any other device on the LAN ports stays a hotspot guest.

    /ip hotspot ip-binding add mac-address=SERVER-MAC type=bypassed

    Test it

    Create a member in the admin panel. On a phone, join the hotspot Wi-Fi, open any web page and log in. Then check the Online now page. The Dashboard has a Router link card. It shows the time and source address of the last login request, the last accounting packet and the last Disconnect request. It also shows how many packets the server dropped because of a wrong shared secret. The card updates every 10 seconds. It is kept in memory, so it is empty after a restart.

    If something fails, see Troubleshooting.
