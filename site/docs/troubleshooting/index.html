    Troubleshooting and FAQ

    Fixes for the usual problems: nobody can log in, Disconnect does nothing, wrong time zone, forgotten password.

    Logins fail

    Nobody can log in, and the login page waits or fails

    Check in this order:

    1. Open the Dashboard and look at the Router status panel. If no login request arrived, the router does not reach the server: check <SERVER-IP> in /radius and that UDP 1812 and 1813 are open on the server.
    2. If the panel counts packets with a bad shared secret, the secret on the router differs from the one on the Settings page. The server drops such packets without an answer. Make them equal.
    3. If the router log says RADIUS server is not responding but the server log shows replies being sent, the router is ignoring them. A common cause is a server on the hotspot network. See Router setup.
    4. Check that the profile has use-radius=yes and login-by=http-pap.
    5. Look at the server log (HSP_LOG_LEVEL=debug gives more).
    The page shows a code such as OUT_OF_BULK

    You use the MikroTik default design, which shows the raw code. Use one of the 7 themes, or write your own texts in the MESSAGES block. See Translate the messages.

    A login is rejected with UNSUPPORTED_AUTH_METHOD

    The router sent CHAP. Set login-by=http-pap on the hotspot profile, as in the setup script. The server writes a warning to its log when this happens.

    A member says the account is used by someone else (NO_MORE_SESSION)

    The member is at the plan's limit of simultaneous devices. After a router restart, old sessions can stay in the list until the router's accounting stops for them. A session ends after the accounting interval plus 60 seconds without an update, or you can disconnect it on the Online page. You can also raise the plan's Simultaneous devices.

    A voucher says the plan period has ended (NO_ACTIVE_SUBSCRIPTION)

    The period starts when the voucher is created, not at the first login. A voucher that waited longer than the plan's validity is already out of date. Make the batch closer to the day of use, or use a plan that renews automatically, or renew the member.

    Router and usage

    Disconnect does nothing, or the admin panel shows an error
    • On the router, run /radius incoming set accept=yes port=3799, with the same port as Disconnect (CoA) port on the Settings page.
    • Check that the router accepts UDP 3799 from the server in its firewall.
    • The server sends the Disconnect to the address the router used for accounting. If that was an address on the router's uplink side, the router's default firewall drops the packet, and the result is no answer. Make sure the router talks to the server from an address that its firewall accepts.
    • The Router status panel on the Dashboard shows the result of the last Disconnect. The server log has a disconnect line for each one, with the address, user, session and result.

    If the router answers that it has no such session, the server treats it as done and ends the session in its list.

    Usage is not counted

    The router must send accounting. Check radius-accounting=yes on the profile and that the Router status panel on the Dashboard shows accounting packets. The usage updates arrive every accounting interval.

    Admin panel, server and settings

    The times are wrong, or vouchers expire at the wrong hour

    The default time zone is UTC. Set yours on the Settings page, for example Europe/London. Dates, daily usage and voucher expiry follow it.

    I forgot the admin password

    Run hotspotpluslight admin set-password on the server (add --env-file if you use one). See First login.

    The server does not start
    • HSP_SECRET_KEY cannot decrypt settings.key_check: this is not the key that the database was made with. Use the right key, or restore a database that fits it.
    • An error about a port: another program uses it. Change the address on the Settings page, then restart. If the panel does not start at all, reset the saved addresses: stop the server and run sqlite3 data/hsp.db "UPDATE settings SET admin_addr=':8081', radius_auth_addr=':1812', radius_acct_addr=':1813';". The env vars HSP_ADMIN_ADDR, HSP_RADIUS_AUTH_ADDR and HSP_RADIUS_ACCT_ADDR only seed the first start. If one of them is set and differs from the saved value, the log shows an env var ignored warning.
    • The message hsp.key is missing but hsp.db exists: restore hsp.key from your backup, or set HSP_SECRET_KEY. The server never makes a new key for an existing database.
    • On Windows, read hsp.log next to hsp.env.
    I cannot open the admin panel

    Use http://SERVER-IP:8081/admin, with http and not https. Check that TCP 8081 is open in the server firewall, and that the admin address on the Settings page is not bound to a different address. /healthz should answer ok.

    Where are the logs?

    The server writes logs to stderr. With systemd use journalctl -u hotspotpluslight. As a Windows service they are in hsp.log. Set Log format to json and Log level to debug on the Settings page, then restart. (HSP_LOG_FORMAT and HSP_LOG_LEVEL only seed the first start.)

    Can I put it behind HTTPS or on the internet?

    No. The admin panel is made for a local network and speaks plain HTTP. Do not expose it to the internet or to the hotspot network.
