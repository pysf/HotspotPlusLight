    Troubleshooting and FAQ

    Fixes for the usual problems: nobody can log in, Disconnect does nothing, wrong time zone, forgotten password.

    Logins fail

    Nobody can log in, and the login page waits or fails

    Check in this order:

    1. Open the Dashboard and look at the Router link card. If no login request arrived, the router cannot reach the server. Check <SERVER-IP> in /radius, and check that UDP 1812 and UDP 1813 are open on the server.
    2. If the card counts packets with a wrong shared secret, the shared secret on the router is different from the one on the Settings page. The server drops such packets and does not answer them. Make the two the same.
    3. If the router log says RADIUS server is not responding but the server log shows that replies were sent, the router ignores the replies. A common cause is a server on the hotspot network. See Router setup.
    4. Check that the hotspot profile has use-radius=yes and login-by=http-pap.
    5. Read the server log. For more detail, set Log level to debug on the Settings page and restart the server.
    The page shows a code such as OUT_OF_BULK

    You are using the MikroTik default design, which shows the raw code. Use one of the 7 themes instead, or write your own text in the MESSAGES block. See Translate the messages.

    A login fails with UNSUPPORTED_AUTH_METHOD

    The router sent CHAP. Set login-by=http-pap on the hotspot profile, as in the setup script. The server writes a warning to its log when this happens.

    A member is told that someone else uses the account (NO_MORE_SESSION)

    The member is at the plan's limit of simultaneous devices. After a router restart, old sessions can stay in the list until the server sees that the router stopped sending accounting for them. A session ends after the accounting interval plus 60 seconds without an update. You can also kick it on the Online now page, or raise the plan's Devices at the same time.

    A voucher says the plan period has ended (NO_ACTIVE_SUBSCRIPTION)

    The validity period starts when the voucher is created, not at the first login. A voucher that waited longer than the plan's validity period no longer works. Create the batch closer to the day of use. You can also use a plan that renews automatically, or renew the member.

    Router and usage

    Kick does nothing, or the admin panel shows an error
    • On the router, run /radius incoming set accept=yes port=3799. Use the same port as the Disconnect (CoA) port setting on the Settings page.
    • Check that the router firewall accepts UDP 3799 from the server.
    • The server sends the Disconnect request to the address the router used for accounting. If that address is on the router's uplink side, the router's default firewall drops the packet, and the result is no answer. Make sure the router talks to the server from an address that its firewall accepts.
    • The Router link card on the Dashboard shows the result of the last Disconnect request. The server log has a disconnect line for each request, with the address, member, session and result.

    If the router answers that it has no such session, the server treats the request as done and ends the session in its list.

    Usage is not counted

    The router must send accounting packets. Check radius-accounting=yes on the hotspot profile. Also check that the Router link card on the Dashboard shows accounting packets. Usage updates arrive every accounting interval.

    Admin panel, server and settings

    The times are wrong, or vouchers expire at the wrong hour

    The default time zone is UTC. Set your time zone on the Settings page, for example Europe/London. Dates, daily usage and voucher expiry times follow it.

    I forgot the admin password

    Run hotspotpluslight admin set-password on the server. Add --env-file if you use one. If you forgot the user name too, read it with sqlite3 data/hsp.db "SELECT username FROM admin;". See First login.

    The server does not start
    • HSP_SECRET_KEY cannot decrypt settings.key_check: this is not the key that the database was created with. Use the right key, or restore a database that matches it.
    • An error about a port: another program uses that port. Change the address on the Settings page, then restart the server. If the admin panel does not start at all, reset the saved addresses. Stop the server and run sqlite3 data/hsp.db "UPDATE settings SET admin_addr=':8081', radius_auth_addr=':1812', radius_acct_addr=':1813';". The environment variables HSP_ADMIN_ADDR, HSP_RADIUS_AUTH_ADDR and HSP_RADIUS_ACCT_ADDR are used only at the first start. If one of them is set and is different from the saved value, the log shows an env var ignored warning.
    • The message hsp.key is missing but hsp.db exists: restore hsp.key from your backup, or set HSP_SECRET_KEY. The server never creates a new key for an existing database.
    • On Windows, read hsp.log next to hsp.env.
    I cannot open the admin panel

    Use http://SERVER-IP:8081/admin, with http and not https. Check that TCP 8081 is open in the server firewall. Also check that the admin address on the Settings page is not bound to a different address. /healthz should answer ok.

    Where are the logs?

    The server writes its logs to stderr. With systemd, use journalctl -u hotspotpluslight. When the server runs as a Windows service, the logs are in hsp.log. You can set Log format to json and Log level to debug on the Settings page, then restart the server. (HSP_LOG_FORMAT and HSP_LOG_LEVEL are used only at the first start.)

    Can I put the admin panel behind HTTPS or on the internet?

    No. The admin panel is made for a local network and uses plain HTTP. Do not expose it to the internet or to the hotspot network.
