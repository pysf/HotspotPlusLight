# Phase 1 notes: ambiguities and interpretations

1. **Login throttle is per client IP, in memory.** PLAN says "5 failures -> 1 min" without a key. Per source IP (not global) so a LAN guest cannot lock the admin out. While locked, even the correct password is refused (429 + `Retry-After`). Failures older than one lockout period do not count. A restart forgives.
2. **Login is a plain HTML form** (303 to `/admin/members`; 401/429 re-render the page); only mutations use htmx. Login has no CSRF token (no session yet; the cookie is SameSite=Strict).
3. **Unauthenticated requests:** GET/HEAD redirect (303) to `/admin/login`; other verbs answer 401 with `HX-Redirect: /admin/login`. Unknown paths and wrong verbs on unauthenticated requests are not auth-checked (404/405 as chi decides); CSRF is checked only on matched routes, so a wrong verb is 405 regardless of token.
4. **Session cookie has no Max-Age** (browser-session cookie); validity is decided only by the server-side row (sliding 1 h).
5. **`admin set-password`** needs `HSP_DATA_DIR` (and, because it reuses `config.Load`, a valid `HSP_SECRET_KEY`); it does not migrate or seed and refuses if the database or admin row does not exist. `--stdin` (or any non-terminal stdin) reads one line; on a terminal it prompts twice without echo. The prompt/confirmation messages go to stderr; the password is never printed.
6. **Plan form:** empty speed/data/time values are rejected ("Required (0 = no limit)") instead of silently becoming "unlimited". Upper bounds added as guards: duration 36500 days, max sessions 1000, time 5,256,000 min, speed 1e9, data 1e12. Name 1-100 chars after trimming.
7. **Create answers `201`** with `Location: /admin/plans/{id}` and `HX-Redirect: /admin/plans` (the `Location` lets tests learn the new id). PUT/DELETE success is `200` + `HX-Redirect`. For non-htmx requests the same endpoints answer 303.
8. **Warning text** is the PLAN wording for N>=2 and "1 member uses this plan; changes apply to it at their next login" for N=1, in an element with `data-plan-warning`. It stays on the 422 re-rendered form.
9. **Delete checks order:** unknown id (404), default plan (409), members in use (409 with the count). The RESTRICT foreign key still guards a race.
10. **Settings validation ranges beyond the DDL:** site title and secret non-empty (<=100 / <=128), timezone must be a loadable IANA name (`time/tzdata` embedded), `coa_port` 1-65535, `accounting_interval_seconds` 10-86400, `batch_username_prefix` 1-20 letters/digits, `batch_counter` >= 0, `batch_max_count` 1-1000, `voucher_password_length` 4-20, `voucher_help` <=2000 chars, `session_retention_days` 0-36500, URLs empty or http(s) with a host. `default_plan_id` must exist ("" = none).
11. **Secret masking:** the settings page renders the secret in an `<input type=password>` value (so Reveal needs no extra route) with an inline-`onclick` toggle button. The secret therefore appears in the page source of an authenticated admin.
12. **No `GET /static/*` on the admin listener** (PLAN 8.2 lists it for a branding override dir; no feature uses it yet). Assets are under `/admin/static/`.
13. **Members page is a placeholder** (`GET /admin/members`, layout + one sentence) until Phase 2.
14. **Phase 0 test edit:** `TestE0_03_Healthz` no longer asserts that `/admin` is 404 on the admin listener (that was the Phase 0 placeholder; E1.03 now specifies the redirect). E0.10's service list gained `settings`.
15. **E1.11 "dropped" vs "rejected":** with a stale secret the fakenas client gets an error (the reply's authenticator does not verify), with the new one a normal Reject. Whether the server should stay silent for a wrong secret remains Phase 3's decision (see phase0-notes 6).
16. **templ:** generated `*_templ.go` files are committed; `make generate` runs templ v0.3.1100 via `go run` (nothing installed globally). htmx 2.0.4 is vendored in `internal/web/static/htmx.min.js`.
